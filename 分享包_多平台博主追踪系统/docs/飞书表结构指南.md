# 飞书多维表格建表指南

本文档详细说明多平台博主追踪系统所需的飞书多维表格结构。请按照以下步骤创建 5 张数据表，并配置好字段和关联关系。

---

## 概述

需要在同一个多维表格（Base）中创建以下 5 张表：

| 表名（建议） | 配置键名 | 用途 |
|-------------|----------|------|
| 博主 | creators | 存储博主基本信息 |
| 视频 | videos | 存储视频元数据和状态 |
| 视频评论 | video_comments | 存储视频评论数据 |
| 视频数据快照 | video_metric_snapshots | 记录视频数据的时间序列快照 |
| 爬取任务日志 | crawl_task_logs | 记录每次爬取任务的执行情况 |

配置文件 `feishu-base-config.json` 中的 `tables` 部分需要填写每张表的 `table_id`。

## 一、博主表（creators）

**表名建议：** 博主

存储所有追踪的博主信息，是系统的入口表。

### 字段列表

| 序号 | 字段名 | 字段类型 | 必填 | 说明 |
|------|--------|----------|------|------|
| 1 | 博主名称 | 文本 | 是 | 博主的昵称/名称，用于展示 |
| 2 | 平台 | 单选 | 是 | 选项：B站、抖音、小红书、快手 |
| 3 | 平台用户ID | 文本 | 是 | 各平台的唯一标识<br>- B站：MID（纯数字）<br>- 抖音：sec_uid<br>- 小红书：用户ID<br>- 快手：用户ID |
| 4 | 主页链接 | 文本 | 否 | 博主主页的 URL，方便跳转查看 |
| 5 | 头像 | 附件 | 否 | 博主头像图片 |
| 6 | 粉丝数 | 数字 | 否 | 当前粉丝数量（整数） |
| 7 | 是否持续跟踪 | 复选框 | 是 | 勾选后会被纳入日常爬取任务 |
| 8 | 视频列表 | 关联 | 否 | 关联到「视频」表，一对多<br>- 关联表：视频<br>- 是否允许关联多条记录：是 |
| 9 | 简介 | 文本 | 否 | 博主简介/签名 |
| 10 | 备注 | 文本 | 否 | 人工备注信息 |
| 11 | 创建时间 | 创建时间 | 否 | 系统自动生成 |
| 12 | 最后更新 | 最后更新时间 | 否 | 系统自动生成 |

### 单选选项配置

**平台** 字段的选项：
- B站
- 抖音
- 小红书
- 快手

### 建议视图

| 视图名 | 类型 | 过滤条件 | 用途 |
|--------|------|----------|------|
| 全部博主 | 表格 | 无 | 查看所有博主 |
| 持续跟踪 | 表格 | 是否持续跟踪 = 已勾选 | 日常追踪的博主列表 |
| B站博主 | 表格 | 平台 = B站 | B站博主筛选 |
| 抖音博主 | 表格 | 平台 = 抖音 | 抖音博主筛选 |
| 按平台分组 | 看板 | 按平台分组 | 直观查看各平台博主分布 |

## 七、建表步骤详解

### 步骤 1：创建多维表格

1. 打开飞书，进入「多维表格」
2. 点击「新建」→「新建多维表格」
3. 输入名称，例如「多平台博主追踪系统」
4. 系统会自动创建一张默认表，先删掉它

### 步骤 2：创建 5 张数据表

按上述字段说明，依次创建以下 5 张表：
1. 博主
2. 视频
3. 视频评论
4. 视频数据快照
5. 爬取任务日志

### 步骤 3：配置关联字段

关联字段需要在两张表都存在后才能配置。配置顺序：

1. 先创建「博主」表和「视频」表的所有普通字段
2. 在「视频」表中添加「关联博主」字段（关联到「博主」表）
3. 在「博主」表中添加「视频列表」字段（关联到「视频」表，双向关联）
4. 在「视频评论」表中添加「关联视频」字段（关联到「视频」表）
5. 在「视频数据快照」表中添加「关联视频」字段（关联到「视频」表）

### 步骤 4：获取 table_id 并填写配置

1. 打开每一张表
2. 从浏览器地址栏获取 URL，格式为：
   ```
   https://xxx.feishu.cn/base/BASE_TOKEN?table=TABLE_ID&view=VIEW_ID
   ```
3. `base_token` = `/base/` 后面到 `?` 之前的部分
4. `table_id` = `?table=` 后面到 `&` 之前的部分（通常以 `tbl` 开头）
5. 将这些 ID 填入 `feishu-base-config.json` 中

### 步骤 5：验证配置

运行环境检查脚本，验证飞书连接和表结构：

```powershell
python check_environment.py
```

也可以手动用 lark-cli 验证：

```powershell
# 列出某张表的所有字段
lark-cli --profile default base +field-list --as user `
    --base-token YOUR_BASE_TOKEN `
    --table-id YOUR_TABLE_ID --format json
```

## 八、注意事项

1. **字段名一致性**：脚本中使用的字段名必须与飞书表中的字段名完全一致（包括空格和标点）。如果修改了字段名，需要同步修改脚本中的字段名映射。

2. **单选选项顺序**：单选字段的选项顺序不影响功能，但建议按文档中的顺序设置，保持一致性。

3. **附件字段限制**：飞书附件字段有大小限制，封面图片通常不会超限，但如果上传视频文件可能会超限（本系统不上传视频文件到飞书，只上传封面图）。

4. **关联字段双向性**：设置关联字段时建议开启「双向关联」，这样在博主表中也能直接看到该博主的所有视频。

5. **权限设置**：确保 lark-cli 登录的账号对该多维表格有「可编辑」权限，否则无法写入数据。

6. **数据去重**：脚本通过「视频ID + 平台」组合来去重，确保这两个字段在表中是有索引的（飞书多维表格默认对文本字段有索引）。

## 九、常见问题

**Q: 字段名一定要和文档完全一致吗？**
A: 是的，脚本中硬编码了字段名。如果需要修改字段名，需要在对应脚本中找到字段名映射并修改。建议初次搭建时完全按照文档命名。

**Q: 可以增加额外的字段吗？**
A: 可以，脚本只会写入它认识的字段，额外增加的字段不会受影响。你可以自由添加人工备注、分类标签等字段。

**Q: 可以减少字段吗？**
A: 不建议。脚本运行时会尝试写入这些字段，如果字段不存在可能会报错。如果确实不需要某些字段，可以保留字段但不使用。

**Q: 表名可以自定义吗？**
A: 可以，表名只在配置文件的 `name` 字段中使用，不影响功能。但 `table_id` 必须正确。

**Q: 为什么要有5张表，合并成一两张不行吗？**
A: 这是标准的关系型数据库设计范式：
- 博主和视频是一对多关系
- 视频和评论是一对多关系
- 视频和快照是一对多关系
- 任务日志是独立的运行记录
合并会导致大量冗余数据，且难以维护。
